# Agent drawing harness research

This note records the primary-source review behind ExcaliDash's semantic canvas
tools. It is design context, not a claim of protocol compatibility with another
server.

## Sources and useful patterns

- [Official Excalidraw MCP](https://github.com/excalidraw/excalidraw-mcp)
  streams simplified elements, supplies a detailed diagram guide, uses labeled
  shapes, explicit camera updates, checkpoints, and screenshot feedback. Its
  prompt is unusually concrete about minimum sizes, spacing, z-order, text
  positioning, and checking overlaps.
- [yctimlin/mcp_excalidraw](https://github.com/yctimlin/mcp_excalidraw)
  exposes strict batch creation plus element lookup, scene description,
  grouping, alignment, distribution, duplication, viewport control, export,
  snapshots, and screenshots. Its scene description adds type counts, bounds,
  connections, groups, and spatial ordering rather than returning raw JSON
  alone.
- [Napkin](https://github.com/sshwarts/napkin) separates compact semantic
  intents from raw canvas patches. It finds open placement, sizes nodes from
  labels, routes arrows edge-to-edge, batches dependent operations using local
  references, and ends construction with deterministic layout.
- [Excalidraw element documentation](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/api/props/excalidraw-api)
  and the [Excalidraw source](https://github.com/excalidraw/excalidraw) remain
  authoritative for scene updates, element relationships, app state, and
  bindings.

## ExcaliDash audit

The original harness safely owned ids, mutation nonces, snapshots, bindings,
sanitization, and atomic persistence. Its weak drawing quality came from the
agent-facing layer:

- created ids could not be used later in the same tool call;
- geometry edits were limited to moving one element at a time;
- connectors started at node centers and did not reroute after node movement;
- text used a single average character width and did not wrap to containers;
- the summary omitted total bounds, type counts, groups, viewport, and collision
  feedback;
- tool guidance described syntax but offered little layout/readability advice.

## Implemented design

ExcaliDash keeps one atomic `apply_ops` surface and its existing REST API. The
compatible extensions are:

- optional `add_shape.ref` and ordered `$ref` resolution;
- `resize`, `align`, `distribute`, `layout`, and `group` semantic ops;
- edge-to-edge connector geometry recalculated after every successful batch;
- deterministic character-aware text estimates and container wrapping;
- scene bounds, type counts, viewport, groups, and capped overlap warnings in
  structural summaries;
- concise tool/system guidance for minimum sizes, whitespace, batching, layout,
  consistent styling, and using returned warnings.

Raw `import_elements` remains REST-only. Images remain readable/preservable
through the existing scene and file paths but are not generated by semantic
agent ops. Layout is deliberately predictable row/column/grid placement, not a
graph-layout dependency; agents retain control over semantic ordering, and the
implementation stays small enough to validate deterministically.
